## Проверка результата

Что проверили самостоятельно и каким способом?

- Тесты прогнаны на исходном коде (через `git stash` изменений) и на исправленном:
  API 10/16 падают → 16/16 проходят; React 4/11 падают → 11/11 проходят.
  Так проверено, что тесты действительно ловят исходные ошибки, а не проходят всегда.
- Ручное воспроизведение через curl до исправления (500 на #103; 200 и запись
  истории от имени просмотрщика, в т.ч. для архивной #104) и после.
- Сценарий быстрого переключения и сохранения в настоящем Chromium (Playwright)
  на живом стеке с `DEMO_LATENCY=1` и `=0`.
- Атомарность: тест с временным триггером, ломающим INSERT в историю → 500 без
  деталей, источник не изменился.
- `php -l` на PHP 7.4.33 (а не 8.x), `npm run build`, `tools/smoke.py`.

Что исправили или отклонили, если такое было?

- В первоначальном плане модели валидация `source_id` стояла **до** проверки
  существования заявки (сразу в маршруте, как в исходном коде). Это противоречит
  требуемому порядку «заявка → архив → источник». Отклонено: маршрут передаёт
  некорректное значение как `null`, а 400 возвращает репозиторий после проверок
  404/403. Покрыто тестом `test_editor_check_order_ticket_then_archive_then_source`.
- Первый вариант оставлял в выпадающем списке редактора для заявки без источника
  плейсхолдер «Выберите источник» — заменён на «Не указан» по требованию.
- `npm install` переформатировал `package.json`; вернул исходный компактный формат,
  чтобы diff был небольшим, версии тестовых пакетов зафиксированы точно.
